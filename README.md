# Warranty Reminder

A household receipt and warranty manager. Current status: **frontend prototype with mock data**.

The approved interface retains its existing Warranty Vault branding. Google authentication is live
for two configured email addresses. Receipt metadata persists in the configured Google Drive root;
receipt capture analysis remains simulated and images are not uploaded yet. Preferences remain in
React memory and reset on a full page reload.

## Local development

Use Node.js 22.12 or newer and npm 10 or newer.

```sh
npm ci
npm run dev
```

Copy `.env.example` to `.env.local` and provide the Google OAuth client values, a 32-character-or-longer
`AUTH_SECRET`, exactly two comma-separated `ALLOWED_USER_EMAILS`, and `GOOGLE_DRIVE_OWNER_EMAIL`.
Set `APP_URL` to `http://localhost:3000` for local development. Vite loads local `.env` files natively.
Variables prefixed with `VITE_` are public browser configuration and must never contain secrets.

Google Cloud must list this local redirect URI for the OAuth client:

```text
http://localhost:3000/auth/google/callback
```

The separate Google Drive setup callback is:

```text
http://localhost:3000/auth/drive/callback
```

The owner opens **Impostazioni → Archiviazione Drive → Configura archiviazione**, authorizes only
`drive.file`, chooses the existing `WarrantyVault` folder, and copies the displayed one-time values
into `GOOGLE_DRIVE_ROOT_FOLDER_ID` and `GOOGLE_DRIVE_REFRESH_TOKEN`. The latter is secret and must
never be committed. Configure `GOOGLE_PICKER_API_KEY` and `GOOGLE_PROJECT_NUMBER` before starting
that setup flow.

## Checks and production build

```sh
npm run lint
npm run typecheck
npm run build
npm run start
```

The production server defaults to `http://localhost:3000`. Its `PORT` and `HOST` environment
variables can override the listener. `npm run preview` also previews the built application.
Use `npm run format` to format files and `npm run format:check` to check formatting.

Use npm exclusively; commit `package-lock.json` alongside dependency changes.

## Architecture

- TanStack Start and TanStack Router provide React 19 server rendering and file-based routes.
- Vite 8 uses explicit React, Tailwind CSS 4, and TanStack Start plugins, plus native TypeScript path resolution.
- The existing Nitro adapter produces a standalone Node server in `.output/server` and static
  assets in `.output/public`. No deployment provider is configured.
- `src/auth/`: Google OpenID Connect, encrypted HttpOnly sessions, and reusable server-side checks.
- `src/drive/`: isolated Drive OAuth, connection setup, and server-only receipt metadata repository.
- `src/routes/`: `/`, `/home`, `/add`, `/search`, `/archive`, `/settings`, `/purchase/$id`, and
  the authentication routes.
- `src/components/vault/`: application UI; `src/components/ui/`: reusable UI primitives.
- `src/lib/vault-types.ts`: UI-facing receipt and product types.
- `src/lib/mock-data.ts` and `vault-store.tsx`: simulated analysis fixtures and in-memory UI state.
- `src/lib/warranty.ts`: existing warranty display calculations.
- `src/server.ts` and `src/start.ts`: local server error handling; the root route handles UI errors.
- `src/styles.css` and `src/assets/`: the approved design system and receipt samples.

`src/routeTree.gen.ts` is generated by TanStack; do not edit it manually.
The long-term architecture is documented in [the project plan](docs/PROJECT_PLAN.md).
Google Drive now persists receipt metadata only: `index.json`, receipt folders, `receipt.json`, and
trash folders live beneath the configured root folder. Receipt images, OCR, image processing, and
scheduled cleanup remain out of scope. The repository writes `receipt.json` before `index.json` and
rebuilds the index from receipt files when needed. With two users, simultaneous writes can still race
between the final index read and write; no locking service or database is used in this phase.
